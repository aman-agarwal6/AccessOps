# AccessOps backend

Django 5.2 and DRF enforce local lifecycle state; Authlib handles server-side
OIDC authorization code + S256 PKCE. Operators are explicitly enrolled under
`(issuer, subject)`. Their separate workforce link is seeded in the database;
email, username and the sponsor field never establish an OAuth delegation.

## Run and verify

The root Compose instructions are the connected lab entry point. Production
settings require PostgreSQL and `DJANGO_SECRET_KEY`; there is no debug login,
password endpoint, test-user header, or SQLite connected mode. Run from the
repository root (with this directory on the Python path through `manage.py`):

```text
python -m pip install --require-hashes -r backend/requirements.lock
python backend/manage.py migrate
python backend/manage.py seed_demo
python backend/manage.py process_jobs
```

The seed is synthetic and idempotent. It never resets existing lifecycle states,
sets passwords or writes to Keycloak. It pre-enrolls the exact realm subjects
generated by the lab bootstrap. Native SCIM verifies subsequent provider effects.

Disposable tests, from `backend/`:

```text
python -m pip install --require-hashes -r requirements-dev.lock
python -m pytest -p no:cacheprovider
python manage.py check --settings=accessops.test_settings
python manage.py makemigrations --check --dry-run --settings=accessops.test_settings
```

`pytest.ini` selects isolated in-memory SQLite settings. PostgreSQL concurrency
tests are explicitly skipped there. Set `ACCESSOPS_TEST_DATABASE_URL` to an
isolated PostgreSQL test service to run them; Django creates a `test_` database.
Never point test configuration at production. Test settings are not imported by
connected settings. CI targets Python 3.13; local checks can use Python 3.14.

For an isolated PostgreSQL run without any lab database privileges, run
`python backend/run_postgres_tests.py` from the repository root. It builds the
hashed test image, starts a randomly labeled private test network and database
with no host ports, runs the suite, writes `output/postgresql-tests.xml`, then
removes only this invocation's containers, anonymous database volume, network,
and temporary credential files. PostgreSQL test privileges never touch the
connected lab database.

Runtime and test lockfiles pin transitive versions and distribution hashes.
They were generated using pip-tools 7.6.1 against the official PyPI index.
Regenerate deliberately from the two `.txt` input files and review dependency
changes. Install only wheels in the reference deployment.

## Enforcement and bounds

- Every console mutation uses a DB-backed session, CSRF, project/object scope,
  current policy, and a required operation-specific idempotency key. Replays
  reauthorize before returning stored output. The mutation budget is 30 new
  successful operations per principal per minute. Login/callback use separate
  DB-backed minute buckets, keyed by a nonreversible address digest; behind the
  private proxy this intentionally becomes an aggregate lab login budget.
- New grants and department/sponsor transfers require independent, immutable
  approval of the exact intent hash and current policy version, expiring after
  15 minutes. Execution rechecks approver role, scope, status, requester status,
  identity revision, and sponsor acceptance where applicable. Only `read`
  permission is implemented by the reference resource/group connector.
- Authorized revoke/offboard operations do not wait for approval. Their local
  grant revocation, sponsored-agent suspension, task cancellation, audit append
  and durable provider jobs commit atomically. Operator sessions linked to an
  inactive workforce identity are rejected on their next request.
- `POST /api/v1/resources/{id}/read` is an actual protected synthetic resource.
  It accepts an enrolled operator session mapped to its workforce identity, or
  the independent executor token. It rechecks active grants and budgets in the
  database on every call. Use an empty JSON object and `Idempotency-Key`.
- The assistant has a separate persisted task grant: ten minutes, six tool
  calls, one draft, explicit resources and a fixed tool allowlist. It computes
  findings from structured lifecycle facts. Untrusted prose is returned as
  evidence and never parsed into instructions, approvals or remote operations.
  It uses no generative model and requires no paid API. Tests map the injection
  scenario to MITRE ATLAS `AML.T0051.001`.
- Every executor request validates the workforce JWT signature, issuer,
  audience and authorized client through the integration verifier, then performs
  fresh token introspection through a separate, role-free confidential API client.
  That introspection client uses a server-only generated secret; the executor's
  token acquisition uses `private_key_jwt`. The application maps
  the exact issuer and subject and rechecks the local sponsor and task/grant.
  DPoP, token-exchange delegation, custom JWT issuance and arbitrary RAR are not
  implemented. Task grants are application records, not invented JWT claims.
- Provider jobs are at-least-once, not an exactly-once network protocol. Every
  attempt observes current provider state before a repeated effect. Durable
  desired and observed state remain distinct. Expired worker leases are
  recoverable; retries back off and stop after five failures, remaining visible.
  A late remote effect is compared with the latest local desired state before
  verification. Provider convergence and token/session revocation have separate
  bounds: local gates deny the next serialized request after commit, while
  provider changes may remain pending during an outage. Already-running remote
  work cannot be recalled. Reconciliation reports drift; it does not adopt it.
- Audit records form a serialized SHA-256 chain and are append-only through
  application paths. `core.audit.verify_chain()` detects modifications relative
  to the current head. A database administrator can rewrite both records and
  head; this is not a claim of immutable storage or external anchoring.

## Configuration

The lab injects `DATABASE_URL`, `DJANGO_SECRET_KEY`, `OIDC_ISSUER`,
`OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_REDIRECT_URI`,
`OIDC_POST_LOGOUT_URI`, `WORKFORCE_ISSUER`, `DJANGO_ALLOWED_HOSTS`,
`CSRF_TRUSTED_ORIGINS`, and `INTERNAL_API_URL`. The integrations also use the
SCIM/OPA/executor settings documented in the root setup. `REQUESTS_CA_BUNDLE`
trusts the local CA for Authlib; `ACCESSOPS_CA_FILE` does so for HTTPX.
Never disable TLS verification.

`ACCESSOPS_TRUST_PRIVATE_PROXY=1` trusts `X-Forwarded-Proto` only in the Compose
topology where the backend is private and Caddy replaces browser headers.
Do not publish the backend port with this option enabled. Host forwarding is
not trusted. Disable request-query logging for OIDC callbacks.
`ACCESSOPS_SOURCE_COMMIT` and `ACCESSOPS_POLICY_SHA256` label actual connected
run manifests. If absent, manifests state `unrecorded`; no build provenance is
invented. When the policy hash is configured, every policy response must report
that exact bundle hash or authorization fails closed. `export_evidence <run-id>`
exports an existing completed run as JSON.

## Local containment

```text
python backend/manage.py contain freeze --incident INC-100 --reason "Investigating a synthetic security incident"
python backend/manage.py contain disable --target IDENTITY_UUID --incident INC-100 --reason "Contain affected synthetic identity"
python backend/manage.py contain revoke --target IDENTITY_UUID --incident INC-100 --reason "Revoke affected synthetic access"
```

These commands require local console/database access, have no HTTP counterpart,
cannot grant or unfreeze access, and fail transactionally if audit append fails.
Restore access only through a separately reviewed administrative recovery.
The command is local break-glass containment, not a second login mechanism.

Tests isolate provider boundaries; they do not claim a running Keycloak/OPA
deployment has passed. Real connected evidence must be captured from the
separate lab checks and exported with its actual status and provenance.
